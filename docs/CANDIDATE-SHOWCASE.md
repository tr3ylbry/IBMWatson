## Labs Case-Study Draft

ClueLab started as a Fall 2020 University of Arizona text-retrieval assignment:
use Lucene and Stanford NLP to answer Jeopardy-style clues with Wikipedia article
titles. The current prototype turns that engine into a small, explainable game
without pretending it is a general-purpose question-answering system.

This showcase follows a new topic from a player request through bounded source
capture, manual clue authoring, source/editorial review and deliberate local
activation. The player and search engine commit independent answers. The server
scores them against a private key, then shows what the computer actually found
beside the author's supporting passage.

The engineering work is mostly about boundaries: sources versus answer keys,
validation versus factual review, saved guesses versus rerun guesses, and a
successful activation receipt versus the catalog actually running. Small private
JSON saves fit the local prototype; they are not a public hosting architecture.
The nine-document candidate still produces a retrieval miss, and that miss stays
visible rather than being edited away.

The result is a reviewable local candidate, not a published product. Human
approval, difficulty feedback, rights clearance, broader accessibility testing
and deployment security remain separate work. Live assistance is disabled;
this pack used no paid model or generation fixture.

Next: independent review and first-exposure feedback on these five versioned
clues, with actual familiarity/hint/fairness observations. Human-reviewed,
playtested and calibrated coverage are each **0/5 for this candidate**, separate
from **0/60 starter** and **0/5 preserved Jovian**. Public release also needs
third-party/source/naming rights review, screen-reader/cross-browser/device QA,
current dependency/advisory review, auth/rate/resource controls, hosting/backups
and explicit authorization. Nothing was published or deployed.
